# ARION OPS — Roteiro de implantação Windows Server (`v1.4.2` candidata)

Roteiro operacional para atualizar o servidor Windows de produção em `C:\Users\Arion\Desktop\ARION-OPS` (MySQL local + Waitress + `integration_worker`).

> **Importante:** Este roteiro utiliza apenas scripts verificados em `deploy/windows/`. Não altera tags oficiais (`v1.4.0` e `v1.4.1` permanecem intactas) e não executa migração Linux/Docker.

---

## 1. Pré-requisitos e verificação do estado atual

Abra o PowerShell no servidor como o usuário operacional do serviço e acesse o diretório da aplicação:

```powershell
Set-Location C:\Users\Arion\Desktop\ARION-OPS
git status
git branch -vv
git rev-parse --short HEAD
.\deploy\windows\status-arion.ps1
```

Confirme:
- working tree limpo (ou mudanças locais documentadas antes de prosseguir);
- commit atual anotado para eventual rollback;
- `.venv\Scripts\python.exe` e `node` / `npm` disponíveis no PATH (`node -v`, `npm -v`).

---

## 2. Backup obrigatório do banco MySQL

Execute o script oficial de backup **antes** de parar ou alterar qualquer arquivo:

```powershell
.\deploy\windows\backup-arion.ps1
```

Valide que o dump foi criado com tamanho coerente em `..\arion-backups\arion-db-<AAAAMMDD-HHMMSS>.sql`:

```powershell
Get-ChildItem ..\arion-backups\arion-db-*.sql | Sort-Object LastWriteTime -Descending | Select-Object -First 3 Name, Length, LastWriteTime
```

> Não prossiga sem confirmar a integridade e o tamanho não nulo do arquivo `.sql`.

---

## 3. Parada controlada dos serviços (Web e Worker)

```powershell
.\deploy\windows\stop-arion.ps1
.\deploy\windows\status-arion.ps1
```

Confirme que `web: stopped` e `worker: stopped` antes de atualizar código ou aplicar migrations.

---

## 4. Atualização segura do código

```powershell
git fetch origin --tags
git pull --ff-only origin main
git log -n 5 --oneline
```

> Nunca utilize `git reset --hard` ou `git clean`. Se `git pull --ff-only` recusar, inspecione o estado local antes de prosseguir.

---

## 5. Dependências Python e Node

Não houve novas dependências obrigatórias desde `v1.4.1`, mas valide a consistência do ambiente:

```powershell
.\.venv\Scripts\pip.exe install -r requirements.txt
```

Se `node_modules` não estiver presente ou `package-lock.json` tiver sido atualizado:

```powershell
npm ci
```

## 6. Build de produção do frontend (obrigatório)

Esta release adiciona `frontend_src/js/painel/plant-history.js` e consolida `frontend_src/js/qualidade/contacts.js` via `{% arion_js %}`. O build é **obrigatório** para atualizar `arion_geo/static/arion_build/` e `var/arion-frontend-manifest.json`:

```powershell
npm run build:production
```

## 7. Aplicação das migrations no MySQL

Verifique o plano pendente e aplique as 6 migrations aditivas (`configuracoes.0013`, `integracoes.0022–0024`, `qualidade.0017–0018`):

```powershell
.\.venv\Scripts\python.exe arion_geo\gerenciar.py showmigrations --plan | Select-String "\[ \]"
.\.venv\Scripts\python.exe arion_geo\gerenciar.py migrate
.\.venv\Scripts\python.exe arion_geo\gerenciar.py makemigrations --check --dry-run
```

Resultado esperado: todas as migrations aplicadas com `OK` e `No changes detected`.

## 12. Checklist de homologação pós-deploy

1. **Dashboard (`/dashboard/`):**
   - Conferir card **Base CMDB** (Total cadastrado, Ativos, Cancelados, data de referência).
   - Clicar em **Analisar planta** e validar as 3 abas (**Visão geral**, **Evolução histórica**, **Comparação por período**) nos temas claro e escuro.
2. **Cockpit (`/cockpit/`):**
   - Aplicar filtro de período/projeto/UF, clicar em **Planta × Chamados** e confirmar sincronização de filtros e paridade de números com o Dashboard.
3. **GEO Inteligência (`/mapa/`):**
   - Conferir paridade de incidentes válidos, links afetados e reincidentes entre Modo Normal e Modo Apresentação (ex.: Vivo / Bradesco).
4. **Qualidade (`/qualidade/`):**
   - Abrir **Ver estabilizados** (`/qualidade/estabilizados/`).
   - Conferir níveis **R1–R5+** nas Ordens de Qualidade.
   - Validar acesso de `Administrador do Sistema` e `Gestor` no cadastro/edição de **Contatos** (`/qualidade/contatos/`).
5. **Base (`/base/nao-identificados/`):**
   - Conferir carregamento da Central de Não Identificados, filtros e auditoria.
6. **Cancelamentos (`/cancelamentos/dashboard/`):**
   - Conferir que `Multa + Equipamentos + Outros = Total consolidado`.
7. **Logs operacionais:**
   - Inspecionar `var\logs\arion-web.log` e `var\logs\arion-worker.log` por 2–3 minutos sem tracebacks ou falhas de sincronização.

## 13. Verificação opcional de Clima (N3 / Infraestrutura)

Caso a coleta climática não atualize em produção, testar conectividade HTTPS (porta 443) a partir do servidor:

```powershell
Test-NetConnection -ComputerName archive-api.open-meteo.com -Port 443
Test-NetConnection -ComputerName servicodados.ibge.gov.br -Port 443
```

Se houver bloqueio de firewall/DNS ou exigência de proxy corporativo, acionar N3/Infra com a tabela de destinos documentada em [`v1.4.2-candidata.md`](v1.4.2-candidata.md#3-clima-em-produção--diagnóstico-e-checklist-de-infraestrutura-n3).

---

## 14. Procedimento de rollback

Em caso de anomalia crítica durante a janela de deploy:

```powershell
.\deploy\windows\stop-arion.ps1
git checkout <COMMIT_ANTERIOR_ANOTADO>
npm run build:production
.\.venv\Scripts\python.exe arion_geo\gerenciar.py collectstatic --noinput --clear
```

Se for necessário reverter o banco MySQL ao estado exato pré-deploy, restaurar o dump gerado na Etapa 2 (`..\arion-backups\arion-db-<stamp>.sql`) usando o cliente `mysql.exe` configurado no servidor e então reiniciar os serviços:

```powershell
.\deploy\windows\start-arion.ps1
.\deploy\windows\status-arion.ps1
```
